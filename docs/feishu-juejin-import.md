# 飞书 → 掘金一键导入

在掘金文章编辑器点击“从飞书导入”，先在页面内选择文档，再点击“开始导入”。本机服务通过飞书官方 `lark-cli drive +export`，以用户身份导出 Markdown 到临时目录，交给掘金原来的 Markdown 文件输入框，并在正文进入编辑器后删除临时文件。不会发布文章，也不会弹出文件保存位置或文件选择对话框。

## 首次使用

1. 更新代码后重新加载 yukonChromeExtension。开始导入时会检查后台功能版本，发现旧版时自动重启本机服务并等待重连，然后继续导入。
2. 本机需安装官方 `@larksuite/cli`，并完成 `lark-cli` 的用户身份文档授权。已有 CLI 用户授权会直接复用；浏览器里的飞书登录不代替 CLI 授权。Chrome 中登录掘金，本机服务状态应显示已连接。
3. 打开空白掘金文章草稿，点击页面中的“从飞书导入”。
4. 在页面内的选择窗口中选择已打开的飞书文档，或直接粘贴飞书、Lark 的 `/docx/` 或 `/wiki/` 链接，然后点击“开始导入”。官方 CLI 会自动解析 Wiki 底层资源；Markdown 当前只支持新版 docx 云文档，旧版 `/doc/`、表格和幻灯片不能按此格式导出。

列表展示当前 Chrome 配置中已经打开的飞书文档，可刷新列表。上次成功导入的文档会用于预选，每次仍需在选择窗口确认；取消、关闭或按 Esc 不会启动导入。这里不提供飞书云空间的完整目录。

导入时显示“检查 → 飞书导出 → 掘金导入 → 清理”四个步骤和已用秒数。CLI 导出阶段显示查找 CLI、等待飞书返回、校验文件等实际状态；飞书接口不提供完成百分比，因此等待期间显示耗时。图片下载和上传显示“当前张数/总张数”。正文导出、全部图片下载、全部图片上传分别最多等待 90 秒，超时会停止并清理。后台版本较旧时会显示自动更新和重连进度，每次最多自动重启一次；失败会停止，不要求用户跳转设置页手动重启。

## 文件与内容

- 保留官方 CLI 生成的标题、表格、代码块、换行和图片位置，只将飞书图片地址替换为掘金上传结果。已打开的文档使用页面标题作为掘金导入文件名，粘贴链接时使用 `document.md`。
- 临时文件位于系统临时目录的 `yukonChromeExtension/article-import/<本次任务 UUID>/document.md`。
- 临时文件只由本机服务写入，成功和失败都会请求清理。清理前核对实际绝对路径及专用任务标记，不删除用户的下载文件或其他目录。
- 异常退出遗留超过一小时的专用目录，会在本机服务建立下一次浏览器会话时补清理。
- 当前支持最大 16 MB 的 Markdown，以及最多 40 张独立飞书图片；单张图片最大 20 MB，图片总大小最大 80 MB。支持 PNG、JPEG、GIF、WebP，拒绝压缩包、错误 HTML 页面和未识别的图片格式。
- 已有正文的草稿不会被覆盖，请使用空白草稿。

CLI 导出中的 `https://…feishu.cn/file/<素材 token>`（也支持 Lark 域名）图片链接会通过官方 `docs +media-download --as user` 下载，再复用掘金编辑器原生 `uploadImages` 上传到掘金图床。重复图片只下载和上传一次，正文中的多处引用都更新；代码示例和普通文字链接不替换。任何图片下载或上传失败都会停止导入并清理，避免生成缺图正文。成功提示显示转存图片数量。

其他公开图片链接和附件维持原样，飞书的专有标签仍不保证被掘金识别。

## 验证

```powershell
cd .\mcp\cookie-export
npm test
```

自动化测试使用合成 Markdown、CLI 输出、DOM 页面夹具和隔离临时目录，覆盖 CLI 参数与身份、原导出字节、错误格式拒绝、掘金文件读取事件、已有正文保护、完整流程顺序和清理边界。掘金导入入口仍需在真实页面验证。

开发排查可以运行：

```powershell
node .\import-article.mjs '<飞书文档链接>' --inspect
```

此命令仅返回掘金页面 URL、标题、顶部控件和文件输入框元数据，不返回正文，也不导出飞书文档。去掉 `--inspect` 会创建或复用独立测试草稿并通过 CLI 真实导入文档，完成后返回草稿链接及清理结果，不发布文章。
